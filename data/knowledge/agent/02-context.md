# 上下文管理

Agent 的能力上限，很大程度上由"每一轮能看到多少有用的信息"决定。

## 系统提示的三块内容

基础人设、可用技能目录、可用工具清单。工具清单虽然能从请求参数里看到，
但在提示里再明确一次"遇到事实性问题先用工具"，能明显提高调用意愿——
光给 schema，模型常常凭记忆硬答。

## 历史会一路膨胀

多轮对话里，每一轮的完整历史都会重新发过去，成本随轮次近似二次增长。
常见做法有两种：按条数裁剪，或者把早期历史摘要成一段。

裁剪时要小心：工具调用消息和它的结果消息是一对，从中间劈开会让下一次请求
被接口拒绝。裁剪窗口应当对齐到用户消息的边界。

## 渐进式披露

把大量说明性内容全部塞进系统提示是最贵的做法。更好的方式是两级暴露：
提示里只放名字和一句话描述，正文等模型真的需要时再读取。
这样放几十个技能也几乎不增加固定成本。

## 什么时候该压缩

当历史长度超过上下文窗口的一半，或者每轮成本明显上涨时。压缩的目标不是"变短"，
而是保住关键决定：做过哪些约定、排除过哪些方案、当前任务进行到哪一步。
