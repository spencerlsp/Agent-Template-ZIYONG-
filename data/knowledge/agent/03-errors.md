# 错误处理与重试

Agent 的错误处理有一条基本原则：**能降级的就降级，只有核心依赖才报错。**

## 分清楚哪些错该降级

可选能力失败不该阻断主流程：知识库没建索引、某个 MCP 服务没启动、
一个技能文件格式写坏了——这些记一条警告跳过即可，对话照常进行。

核心依赖失败才应该退出：模型端点连不上、没有可用的 API Key，
这些是没法绕过的。判断标准很简单：**缺了它还能不能完成对话**。

## 三层重试

传输层重试交给 SDK 处理，按状态码区分：限流和五次错误退避重试，
权限错误立即失败并给出可读原因。

业务层重试由模型自己完成：工具返回错误文本后，模型会换个参数再试一次，
这是最省事也最有效的一层。

循环层设上限：模型可能陷入"反复调工具但从不给结论"的状态，
所以必须有最大步数，撞上限时明确报错而不是无限等待。

## 资源必须收干净

子进程、数据库连接、HTTP 客户端都要在 finally 里释放。
中断、异常、正常退出三条路径都要覆盖——否则会残留僵尸进程占着管道。
