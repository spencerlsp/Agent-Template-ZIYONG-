# MCP 协议基础

MCP（Model Context Protocol）是工具接入的标准化协议，解决"每个工具都要写一遍适配"
的问题。

## 它解决什么

没有标准协议时，接一个外部服务就要写一套胶水代码：怎么启动、怎么调、结果怎么解析。
MCP 把这些约定固定下来，于是同一个服务器可以被任何支持 MCP 的客户端使用。

## 两种传输方式

**stdio**：客户端把服务器当作子进程启动，通过标准输入输出通信。
不需要端口、不需要常驻服务，配置里写命令和参数即可，适合本地工具。

**Streamable HTTP**：服务器独立运行并监听端口，客户端按地址连接。
适合远程部署或多个客户端共享的场景，代价是要自己管理服务。

## 三个基本动作

握手：客户端启动服务器后先做初始化协商，确认双方版本与能力。

发现：客户端询问服务器暴露了哪些工具，拿到名字、描述和参数结构。

调用：按名字传参数，拿到结果或错误。

## 与本地工具的关系

远端工具发现之后，应当注册进和本地工具同一张登记表。对模型来说两者没有区别，
只在来源字段上留个标记便于排查——接入方式变了，模型侧完全无感，
这是 MCP 最有价值的地方。

## 常见坑

子进程的生命周期必须自己管理：会话要常驻，连接失败时也要把已建立的资源收干净，
否则会残留僵尸进程。子进程还需要继承父进程的环境变量，否则可能找不到解释器。
