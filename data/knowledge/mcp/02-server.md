# 写一个 MCP 服务器

自己写服务器通常是为了把内部系统暴露给 agent，注意事项和写普通库不太一样。

## 工具粒度

一个工具对应一个明确的动作，不要把整个内部 API 原样映射过去。接口的粒度是给程序用的，
工具的粒度是给模型用的——后者需要更贴近任务，而不是更贴近资源。

## 描述是给模型看的

工具描述要写清触发场景和返回什么，而不是复述实现。
参数名用模型能理解的业务词汇，不要用内部缩写。

## 错误要结构化

服务器返回错误时，尽量给出可读的原因和建议，而不是裸的错误码。
模型拿到"文件不存在，可用的文件有 a.md、b.md"这种信息，才有机会自我纠正。

## 超时与幂等

注明哪些操作可能慢、哪些会改数据。写操作要做成幂等的，因为模型可能重试。

## 版本与兼容

工具的 schema 一旦发布就当成接口对待：加可选参数是兼容的，
改参数含义或删除参数会让已经依赖它的客户端出错。
