# 结构化输出

当程序要消费模型的输出时，自然语言是不够的——你需要它返回可解析的结构。

## 三种实现方式

**提示词约束**：直接要求"只返回 JSON，不要任何解释"。最简单，但模型偶尔会加上
前置说明或代码块围栏，解析时要做容错。

**JSON 模式**：请求里声明响应格式为 JSON，模型保证输出是合法 JSON。
比提示词约束可靠，但只保证语法合法，不保证字段符合预期。

**Schema 约束**：把字段和类型写成 JSON Schema 传给模型，由服务端约束生成。
最可靠，适合字段固定的抽取类任务。

## 容错解析

三种常见脏数据要处理：外层包了代码块围栏、前后有多余的文字说明、
数字被写成字符串。解析失败时不要直接抛异常，先把原文记下来再决定是重试还是放弃。

## 校验与重试

结构化输出也要过校验层，和工具参数一样。校验失败时把错误信息回传给模型让它重写，
通常一次就能改对——这比你自己写规则修补可靠得多。

## 什么时候不值得用

需要自然语言表达的场景（解释、建议、总结）不要硬塞进结构里。
结构化的目的是让程序能消费，不是为了好看。
