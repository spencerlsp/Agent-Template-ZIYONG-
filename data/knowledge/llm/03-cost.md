# 成本与延迟

Agent 的成本几乎全部来自 token，而它随"轮次 × 上下文长度"增长。

## 成本从哪里来

输入 token 是主要开销：每一轮请求都要把系统提示、工具定义、完整历史重新发一遍。
多轮对话里输入量的增长近似二次曲线，这是长会话最容易被忽视的成本。

输出 token 单价通常更高但量小。工具定义也常被低估：十个工具的 schema
可能占掉上千 token，而且每一轮都要重发。

## 四条降本途径

**压缩历史**：摘要早期对话，只保留关键决定。

**按需暴露工具**：工具多了之后，默认只给常用的一批，其余通过"列出工具"动态加载。

**缓存重复前缀**：系统提示和工具定义每轮都一样，部分供应商支持缓存这段前缀，
命中后输入价格大幅下降。

**换小模型做简单活**：分类、抽取、改写这类任务不需要最强模型，
按任务难度分流能省下大部分成本。

## 延迟的来源

首 token 延迟主要取决于输入长度；总时长则受输出长度和工具调用轮次影响。
流式输出不减少总时长，但能显著改善体感——用户看到字在动，等待就不那么难熬。
