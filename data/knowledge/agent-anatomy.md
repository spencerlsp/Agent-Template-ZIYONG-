# 一个本地 Agent 的构成

本地开发 agent 通常由六个部件拼成，每个部件都可以单独替换。

## 模型调用层

负责和模型说话：拼请求、解析回复、处理工具调用、流式输出。它的价值在于隔离差异——
换一家供应商只改这一个适配器，上层代码一行都不用动。

## 工具（Function Calling）

模型不能执行代码，只能"点菜"：它输出一段结构化的调用请求，由你的程序执行，
再把结果回填给它。因此参数校验和权限边界必须在你的代码里做，不能指望模型自觉。
工具报错时要返回错误文本而不是抛异常，这样模型才有机会换个参数重试。

## 技能（Skill）

技能是写给模型看的流程说明。它和工具的区别在于：工具是原子能力，技能是
"遇到这类任务该怎么做"。技能通常按需加载——系统提示里只放名字和一句话描述，
正文等模型真的需要时再读，这种做法叫渐进式披露。

## MCP

MCP（Model Context Protocol）是工具接入的标准化协议。客户端连接 MCP 服务器，
发现自己可以用哪些工具，再把这些工具和本地工具放进同一张登记表——
对模型来说，远端工具和本地工具没有任何区别。

## RAG

检索增强：先把文档切块、向量化、入库，回答问题前先检索相关片段作为上下文。
它解决的是"模型不知道你的私有文档"这个问题。

## Agent 主循环

"推理 → 行动 → 观察"的循环：模型决定要不要调工具，程序执行工具并把结果喂回去，
直到模型给出最终答案或达到步数上限。这个循环是前面所有部件的黏合剂。
