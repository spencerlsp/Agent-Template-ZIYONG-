# 怎么测一个 agent

Agent 的测试比普通程序难：输出不确定、依赖外部服务、失败方式还很隐蔽。

## 分层测试

**单元测试**：切块、检索融合、参数校验、历史裁剪这类纯逻辑，输入确定输出确定，
用普通测试即可。它们守住的是"不许退化"的底线。

**循环测试**：用一个确定性的假模型驱动主循环，断言事件序列、工具是否被真正执行、
消息是否按协议落库。假模型让"模型行为"从变量变成常量。

**质量评测**：召回率、命中率这类指标，数字可以波动，不设通过线，
但每次改动后都要对比。

## 假模型的价值

给模型写一个离线替身，按脚本返回预设回答。好处是整条链路能在没有网络、
没有密钥的情况下跑通并可测试——链路是否因此完好，就成了一个随时可验证的事实，
而不是等 CI 里才发现的问题。

## 观察式测试

有些问题没有断言能表达，只能靠人看。比如检索出来的片段边界是否合理、
模型引用出处是否准确。做法是把输出打印成人类可读的形式，定期人工扫一眼——
这不是偷懒，而是承认有些质量维度暂时没法自动化。

## 别测模型本身

"模型这次回答得好不好"不是测试能稳定断言的，它随版本、温度、提示词波动。
测试应该盯住你自己写的那部分：数据流、边界条件、降级路径。
